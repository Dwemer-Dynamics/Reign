# Tavern portrait source pack procedure

This provider-free import joins the existing persistent native renderer to the ordinary portrait pipeline. It is for the authored 284-person town cast, not campaign capture or shared-portrait rebuilds. It creates no listener and makes no provider calls. Use the Reign validation plan/validator before invoking changed executables; source inspection or a successful import does not establish native visual acceptance.

1. Prepare `native-source-manifest.json`, the 284 immutable snapshots, and `native-render-batch.json` in one task-owned directory. Each snapshot must match the validated `ReignBeta/ModuleData/reign_tavern_cast.json` identity, native BodyKey, age, sex, physique, and complete civilian equipment. The explicit profile is `ai_source_resident_full_outfit_v1`. Use native request version 4, batch version 3, render 1536×2048, output 768×1024, crop scale 1, vertical center 0.5, pitch 0, and `preserveEncounteredOutfit=true`.
2. After acquiring the normal native-operation gates, run the exact validated `Bannerlord.NativePortraitRenderHost.exe` with process-local `BANNERLORD_GAME_PATH` and `REIGN_NATIVE_PORTRAIT_JOB=<absolute native-render-batch.json>`. Use the game's `bin/Win64_Shipping_Client` working directory and arguments `/singleplayer _MODULES_*Native*SandBoxCore*Sandbox*StoryMode*CustomBattle*NavalDLC*BannerlordNativePortraitRenderer*_MODULES_ no_watchdog /suppress_message_boxes /DisableErrorReporting`, omitting optional uninstalled modules. Verify the installed renderer module against its validated artifact first. The supported host owns its private desktop, renders the entire batch in one engine, then exits. Do not load or advance a campaign.
3. Require batch status `complete`, `total=284`, `completed=284`, `failed=0`; every row must have its own complete version-4 job result, exact effective body properties and output path, and a valid 768×1024 source PNG. Inspect native image evidence for correct people/outfits/full-body framing. Retain the validated helper hashes, job manifest, results, and source hashes with task evidence. A caller-authored JSON status file alone is not proof that the native renderer ran.
4. Import with the validated server executable: `ReignBetaServer.exe --import-tavern-native-sources <absolute native-source-manifest.json> --pack-campaign tavern_pack_01a0979f`. The command resolves its current authored cast from the packaged verification fixture and prints JSON plus a nonzero exit code on failure. `--import-tavern-native-sources help` prints bounded CLI help. Process-local `REIGN_DATA_ROOT` selects the target data root. Prefer an isolated task data directory for staging; if importing into the installed server data root, stop the visible server lifetime group first. A staged exact source subtree can be installed only through the coordinated deployment workflow.
5. The importer validates every input before publication. It rebases a copy of each snapshot into the dedicated task pack campaign and binds the new canonical snapshot hash; the original input hash remains in its receipt. It writes unchanged source bytes, receipts, and ready `request.json` payloads beneath `native_portrait_sources/tavern/<packId>/<CastId>/`. A directory rename publishes the complete pack atomically. Identical retries retain the same pack and bytes; conflicting existing packs fail. No `_shared` portrait is read, written, rebuilt, or seeded by this route.
6. After the existing paid provider gate, send each emitted `request.json` to the existing `/portraits/generate` endpoint on the supported visible server. Keep its dedicated campaign ID and `preparedNativeSourceId`. The server accepts only opaque pack/cast IDs from its own source store and rechecks published receipt/source hashes and the exact request snapshot. Unknown, changed, cross-campaign, shared-output, or wrong-profile prepared references fail before a renderer/provider can be used. Do not replace these requests with scenery requests or arbitrary supplied images. Current Portrait Images settings determine the provider/model. The full-outfit selector preserves the native clothes and suppresses a second clothing-redesign pass; all normal physique prompts, provider routing, face/composition checks, output normalization, product receipts and failures remain active.
7. Gather only successful validated portrait masters into `TavernHousePortraits/<CastId>/portrait.png`. Require all 284 CastIds, record their product receipts and master hashes, and package the exact bytes through the coordinated deployment inventory. The native seed maps each authored CastId to its actual saved HeroId when that town is opened. Missing initial images retain native fallback and the explicit eye request, without automatic bulk provider calls.

## Security and recovery

The import CLI is a local, explicit preparation operation; it accepts no HTTP import and does not change image settings, credentials, live campaign state, or shared caches. Input artifacts must stay beneath the manifest directory. Output is confined to the selected server-local store. Absolute paths, size limits (10 MiB/source, 512 MiB/pack), exact cast membership, full native body/equipment/framing checks, and reparse-point rejection apply. Requests cannot supply filesystem paths. Keep generation evidence and use an isolated task namespace; do not point the import at another task's generated or shared portrait directories.

Contract coverage is `RunPreparedTavernPortraitSourceTests` in the existing tavern/characters Verification Lab suite. Its five provider-free cases cover exact native binding, snapshot/source/scope/physique integrity, immutable publication retries, confined IDs and paths, and rejection of a final failed source before any part of a complete authored batch is published. Synthetic contract images verify routing and integrity only. They do not replace native rendering, visual inspection, provider output acceptance, or campaign UI acceptance.
