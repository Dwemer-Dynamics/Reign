# Reign Linux deployment and client artifacts

## Unstable tester distribution

The installer fixes the socket-only PostgreSQL cluster at port5432, rather than Debian's host-port discovery default. The explicit native probe isolates PostgreSQL, server and Apache together. Dependency RECORD verification permits a missing generated `__pycache__/*.pyc` only when its hashed source is recorded and verified; existing cache files remain hash checked and all skips are reported. No source or native library omission is permitted.

The source-controlled implementation is `ReignServer/scripts/tester-package`: `build_package.py`, `Install-Reign.ps1`, `Start-Reign.ps1`, clean-image preparation/audit and provider-free contracts invoked by `TesterPackageTests`. Package assembly requires a `reign-tester-image-receipt-v1`; native installation and game acceptance remain separate.

User requirement, 2026-11-14: every publication of the completed latest full build targeting `unstable` includes one large ZIP uploaded to the user's Google Drive, suitable for sharing with testers. Include both the matching server and its installation system, the Reign mod itself, and the latest instructions HTML. This applies to the draft-PR publication route as well as an explicitly authorized branch promotion; it does not authorize merging a draft or publishing to `dev`/`reign`.

Use the exact successful manifest-selected Release artifacts and canonical Linux component, without rebuilding unchanged qualified source. Bind both source revisions and artifact/report fingerprints in a package manifest. Include the complete distributable ReignBeta module and tracked shared-portrait inventory, its required Windows portrait helper, Linux server payload, supported dedicated-WSL installation/lifecycle scripts and declared prerequisites, and current HTML instructions with every required local stylesheet, script and image. Do not substitute a source archive, developer deployment script requiring absent checkouts, historical installer or incomplete payload for an installable build.

Keep saves, campaign portraits, private settings/credentials, runtime databases, logs, caches, licensed game assemblies and unredistributable dependencies out of the ZIP. Preserve third-party licensing and document externally installed prerequisites. Validate package contents and hashes against the qualified artifacts, check the extracted instructions' links/assets, and exercise the supported installer in an isolated environment where available. Record native/clean-install acceptance gaps separately; never label an untested or incomplete installer as verified.

Retain the package and durable inventory/hash/upload receipts under `E:\CodexStorage\Projects\Reign` per the storage policy. Discover and reuse an appropriate existing Drive destination; otherwise upload to My Drive without reorganizing existing files. Verify uploaded name, size/checksum when available, file ID and download/view link through Drive metadata readback. Preserve existing sharing settings unless the user authorizes changes. Publication is incomplete if packaging or upload is blocked; report the exact missing capability or prerequisite and preserve the recoverable checkpoint.

### Dedicated-WSL installer procedure

Prepare a new task-named Debian12 image from the exact upstream OCI digest in its base-provenance receipt. Never export a player distro. `prepare-image.sh <support-directory> <immutable-dependency-archive>` blocks service startup before apt and prevents database-cluster creation. Its dependency archive contains only the requirement-hash venv and model-lock-hash model directories. Strip newly generated snakeoil TLS keys, machine identity and transient logs before export. `audit_image.py` binds the exported bytes, upstream provenance, OS package versions, locks and clean-state exclusions. Reuse compatible audited images rather than rebuilding unchanged dependencies. Creation/cleanup of a task-owned image needs the current task's artifact/test authorization; it grants no authority over another distro.

After committing and qualifying the final paired source, assemble without recompiling:

```text
python ReignServer/scripts/tester-package/build_package.py --workspace <Reign-root> --server-workspace <ReignServer-root> --validation-report <original-Release-all-or-product-report> --linux-report <original-Linux-report> --verifier <independently-qualified-MCP-assembly> --verifier-sha256 <reviewed-assembly-hash> --image <clean-image.tar> --image-receipt <audited-image.json> --guide <latest-single-file-player-guide.html> --output <new-E-distribution-directory>
```

The qualified read-only source checker rejects stale/foreign reports or changed artifacts. The builder also rejects dirty tracked source, links/case collisions, unhydrated portraits and mismatched dependency-image locks. It packages the complete module/helper, matching server/controls, offline image, current available HTML manual, fresh `INSTALL.html`, component notices and per-file manifest. It reads every ZIP member back and compares hashes. Publish the separate ZIP SHA receipt alongside its link; an in-package hash manifest proves accidental integrity, not distributor authenticity.

Exercise the actual extracted package using a task-named distro, isolated game fixture and explicit isolated `-InstallationFile`. Assert production installation/PIDs/listeners remain unchanged. Default services stay stopped; use an isolated network namespace for server/worker runtime proof when production owns the normal ports. Distinguish clean-install, launcher, upload, another-computer and native-game acceptance. Updates need exact tester ownership and a retained local pre-update export. Failed imports/unknown files remain for inspection. Never automatically unregister a tester distro or restore its database to conceal failure; code rollback does not undo migrations. Normal provider-free fixtures never create distros or call live installers/providers.

`runtime_probe.sh` is an explicit native acceptance command, never a routine-test entry. Invoke only inside the task-owned `ReignTester*` distro with its exact owner ID, an empty run-owned `native-saves` directory under `.codex-build/tester-distribution`, expected qualified server DLL SHA and `/var/tmp/reign-tester-proof-<owner>.json`. It rebinds only the fixture's save bridge, refuses existing campaigns/active fixture services, verifies pinned dependency versions/RECORD hashes, and uses a named network namespace plus runtime-only systemd drop-ins for actual service/worker/CGI stop/start proof. `reign-tester-runtime-proof-v1` records PIDs, schema, loaded384 and isolation; cleanup stops the fixture and removes only its own drop-ins/namespace. Compare the real installation record, unrelated registrations and production health before/after. No campaign/save advancement, providers or game launch is authorized by this command.

ReignServer targets `linux-x64` only and runs in its own separately registered `ReignServer` WSL distro. Windows remains the Bannerlord client and native portrait-renderer platform. There is no standalone Windows server installer or packaged Windows vector worker.

Use the canonical validator for product validation and `ReignMcp/scripts/reign-validate.ps1 -LinuxServer -Restore -RequestingTaskId <task UUID>` for the self-contained Linux artifact. The Linux report records its source fingerprint and file inventory. Private verification source is excluded from published server artifacts.

Deploy validated artifacts with `ReignServer/scripts/Deploy-LocalWsl.ps1`. The Windows portrait helper is built with the client. Preserve `ReignServer/data` and retained `ReignServer/runtime` builds, campaigns, credentials and the PostgreSQL database. A deployment does not authorize a release or establish native/in-game acceptance.

Server verification runs in WSL when Codex runs on Windows as the `reign` user. The canonical process runner requires `REIGN_VALIDATION_MODE=1` and `REIGN_DB_NAME=ReignValidation`, maps run-owned paths, and bounds the Linux child process group. The selected distro is `REIGN_WSL_DISTRO` (default `ReignServer`). Never point validation at the production database or data directory.

Approved first-party shared portraits belong in the private Reign module at ReignBeta/PortraitCache/_shared, with the tracked ReignBeta/PortraitCache/shared-portrait-inventory.json. Deploy and package the verified module inventory; do not rely on a separate or machine-local first-party portrait payload.
