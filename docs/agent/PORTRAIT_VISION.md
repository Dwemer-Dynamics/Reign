# Character portrait vision and text generation

Text based is the default for new and legacy settings without an explicit method. The controls at the top of AI Image Generation select `portraitGenerationMethod` (`text` / `image`), `portraitVisionProvider` (`Codex` / `NanoGPT`) and a separate per-provider vision model. Vision and image models are independent: the Codex selector uses the cached account catalog; `runtime-default` resolves the actual discovered default with image input capability. The built-in Codex image tool has no model override. NanoGPT uses `portraitVisionNanoGptModel`, defaulting to `deepseek/deepseek-v4.1-flash` at the user's request for a stronger accuracy-focused option; switching providers retains both selections. Explicit saved model choices are preserved. NanoGPT's 2026-10-07 catalog advertises vision and structured output for this model, but labels its route a rate-limited beta with limited capacity. Catalog capability and published model results do not establish portrait-specific accuracy. Live quality remains unmeasured.

NanoGPT discovery uses its public `GET /api/subscription/v1/models?detailed=true` catalog, filters explicit `capabilities.vision`, and caches successful results for ten minutes. Requests use the saved NanoGPT text API key and `POST /api/subscription/v1/chat/completions`, without explicit provider pinning or a paid endpoint fallback. A model must still appear in the current subscription vision catalog at request time. Image detail is explicitly high to retain fine facial cues. DeepSeek structured-output requests use its documented `json_object` format; other structured-output models receive the JSON schema. Every model receives the same explicit JSON instructions and strict local seven-field validation; models without structured output receive no unsupported response-format parameter. Schema errors, refusal, tools, truncation, rate limits and quota exhaustion fail the portrait operation without another billable retry. Account billing preferences remain provider-owned. Discovery does not prove entitlement or output quality.

For ordinary character generation and Look Again, Reign resolves the authoritative native source and validated independent weight/build, then calls the selected vision provider. Codex uses an ephemeral job-owned request; NanoGPT uses a subscription vision LLM call. Seven bounded JSON fields describe face, eyes, hair, facial hair, marks, outfit and uncertainty. Source pixels are data, never instructions; tools, shell, MCP, agents and image generation are disabled for vision. The normal image provider receives the written identity plus existing complete composition, culture clothing, physical-confidence, photographic, output and physique layers, without the native image. Native source bytes, description, actual vision model, hashes and timings remain in the product provenance and first generation stage.

Encountered residents retain the described equipped outfit, bypassing cultural outfit replacement. The adult clothing pass keeps existing eligibility (ordinary adult female physical confidence >=61; existing Tavern rules) and receives the completed normal portrait as its reference. Its failure preserves the normal result. Explicit Image based keeps the previous native-reference path. Scenery, shared existing-AI outfit-preserving rebuilds, outfit edits and Reflect on the Years keep their reference-image contracts. Vision failures stop before normal/adult generation and retain the existing portrait; there is no silent image-based fallback.

NanoGPT/OpenRouter omit references for text generation. Atlas uses the corresponding documented text endpoint in the same model family and skips source upload; image/adult edits retain their edit endpoint. Provider credentials/selections are preserved. Refresh Codex's catalog in API Settings to populate available vision choices; missing catalog data retains the saved choice, and request-time discovery validates it before inference. Catalog listing does not prove entitlement.

Provider-free proof: canonical `changed` validation selects the manifest tier for the exact paths. `RunPortraitVisionContractTests` runs inside the existing image-generation contracts, alongside adult, physique and refresh regressions. The shared `portrait-profile-ui-contract.mjs` renders isolated exported `control-center.html`; all HTTP requests are intercepted and settings remain in memory. It covers both methods, model persistence, catalog failure, normal/adult independence, keyboard and responsive layout. No native prefab, portrait aperture or approved raster shell changes; raster-reference/native-rendering requirements are inapplicable to these web form controls. Live SDK vision, generated-art likeness/photorealism and in-game acceptance remain separately gated follow-up evidence.

The staging trial used manual visual inspection, not an automated vision API. Its reviewed cultural references and uncertainty practices informed this implementation; its safe court clothing trial does not replace Reign's adult confidence routing. No automatic post-generation visual review or unlimited retries are added.
