# Player god mode

2026-11-11 user request: toggle player god mode in any fight with **Alt+=** (the equals key; left or right Alt). The implementation uses Bannerlord's native `Agent.MortalityState.Invulnerable` through a mission-local `ReignPlayerGodMode` behavior.

- Off on entering a mission. Available to an active, living, human player-controlled main agent in Battle, Duel, Tournament and Stealth mission modes. No multiplayer, deployment, conversation, cutscene or spectator activation. Ctrl/Shift variants do not toggle it.
- Press Alt+= once to enable; press it again to disable. Native informational messages confirm ON/OFF. No Reign prefab, artwork, panel or layout changes.
- Protect only that main agent. Do not modify the horse, allies, enemies, weapons, damage models, current health or campaign hero. It does not heal, revive, confer one-hit kills or enable the game's global cheat mode.
- Restore the captured prior mortality state when toggled off, leaving combat mode, replacing/losing the player agent, ending the mission or removing the behavior. Do not blindly set Mortal: another system may have supplied Immortal/Invulnerable beforehand. If another system has since changed mortality away from Invulnerable, leave its state alone and release ownership.
- Leaving combat or changing the controlled agent reports OFF. A hideout boss conversation therefore turns protection off; press Alt+= again when the duel begins. A return to combat does not silently re-enable it. If another system already granted invulnerability, turning Reign's toggle off restores that existing protection rather than revoking it.
- Enabled state belongs to the mission behavior and is not serialized. A cleared-on-release static pointer provides an O(1) health-write guard without scanning mission behaviors for every soldier. Every new mission needs an explicit toggle. No save-schema change or automatic protection on loading a save.
- Install the exact, owner-scoped `Agent.Health` setter prefix in `OnBeforeInitialModuleScreenSetAsRoot`, after the native animation table loads. Before touching Agent or ActionIndexCache, query `MBAnimation.GetActionCodeWithName("act_inventory_idle_start")` directly and defer if unavailable. Early Agent initialization can retain invalid animation IDs for the lifetime of the process. This also blocks RBM's direct fist/self-damage health decrease for the protected agent; native collision flags alone do not cover that path. Refuse activation without changing mortality if patch installation fails, log the failure and show a native informational message. Removing Reign's patch must retain other Harmony owners. No per-tick health refill.
- A failed install is retried only on another explicit toggle press, allowing recovery after another module finishes loading; there is no automatic per-tick retry/log loop. Do not activate on zero, negative, NaN or infinite current health. Reflection writes to native backing fields or explicit forced-death/despawn APIs remain outside the ordinary health-write guard.
- Registration is idempotent. Module unload restores active mortality and clears the cached behavior before removing the owned health prefix. SetMortalityState/CurrentMortalityState are managed assignments in the inspected Bannerlord 1.4.8 assembly; teardown deliberately avoids adding native IsActive/agent-list calls. A forced script death/despawn that bypasses health and mortality checks is outside ordinary combat invulnerability.
