## Behavior

The saved `reign-wanderer-population-v1` identity ledger decouples the Native skills template from the person. The catalog is the Cartesian product of exact Native wanderer templates and cultures present in loaded towns/kingdoms. Seven reviewed name grammars cover Empire, Vlandia, Sturgia, Battania, Aserai, Khuzait and Nord. An unsupported culture is an explicit coverage failure, never a Vlandian/name/face fallback. Cultures are selected independently of tavern location so travelers from every culture circulate globally.

Creation preserves the template skills and general specialization. A culture/sex/race-compatible native wanderer closest in skills supplies cultural equipment and voice; a cultural civilian supplies the face range, or serves as the equipment fallback if no wanderer donor exists. Native personality traits receive small bounded differences. A fresh, saved personal biography records a local birthplace and professional experience without inheriting the source template's specific identity/history. Existing Reign construction enriches these saved facts on first contact; population maintenance never calls an AI provider.

Names have global given-name collision and near-name rejection against current heroes and every reserved wanderer name. New bodies are rejected both by static key and facial-structure distance against existing adult heroes and reserved retired faces. The shape metric excludes age/height/weight/build, so changing hair or age cannot make the same face eligible. Native face constraints apply; candidate exhaustion is reported and deferred. Visual diversity still requires rendered native acceptance; numerical shape distance alone is not human visual proof.

The normal available population is four per town (desired band 3-5). Existing surplus moves before new people are created. Each maintenance tick can create/move one person and each daily maintenance at most four. A safe current-town menu is the preferred underfilled target so the town the player is visiting tops up promptly; no creation or movement occurs during an active mission or siege. Native recruited companions, prisoners, party members, governors and children do not satisfy the available population. Quest-tracked heroes do not move/rotate. Population target is eventual, but a visited town no longer remains starved merely because the player is there. Counts above five are surfaced, never solved by deleting protected people.

Native creation, template-count-based replenishment, random cleanup and swapping are suppressed only after the Reign behavior successfully initializes. The initial Native roster in a new campaign and all existing saved wanderers are adopted without renaming/re-facing them. Existing duplicates are preserved as a legacy condition; the generator introduces no new name/face collision. The daily rotation opportunity remains one global 10% chance, restricted to eligible, unprotected people at least 30 days old in the ledger. Daily swaps preserve both tavern counts and require seven days since the last move.

## Contact and saves

`_reign_wanderer_population_v1` uses the existing bounded save-payload codec. Accepted names, native hero IDs, static bodies, face-shape reservations, template/culture provenance, biographies, generation cursor, contact receipts and retirement history survive save/load. Native hero state is authoritative after creation; initialization never reapplies the generated body/name or revives absent/dead heroes.

Actual nonempty individual, party or social Reign chat protects its speaker. Automatic openings, inspection and bystanders do not. Before a request, its subject becomes ineligible for rotation; after a successful reply the first receipt becomes immutable. On uncertain failure, history remains unchecked and retirement is withheld until an observational reconciliation succeeds. Concurrent requests are reference counted. Campaign/behavior/timeline changes reject late completions.

The existing `/dialogue/history` endpoint accepts `wandererContactOnly=true` with exact campaign, active timeline, native hero and player IDs. It reads paired canonical player/NPC turns, the saved profile protection and older per-hero dialogue history; it does not construct profiles, consume providers, mutate native state or create protection itself. A capped unresolved history is not evidence of no contact. Existing campaign Save Sync isolation owns the database/file snapshot boundary. The client applies the resulting receipt to its own save ledger.

Per the user's approved wording, contacted heroes cannot die except by old age: both `CanDie` and forced `KillCharacterAction.ApplyInternal` honor this rule. This includes battle, execution, murder and background `Lost`. Existing game life/death settings may still disallow old age. If the user instead chooses only background-removal protection, change the explicit pure death policy and its contracts together. Recruitment/dismissal and later occupation changes never erase contact protection.
