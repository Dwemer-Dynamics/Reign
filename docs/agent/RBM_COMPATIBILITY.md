## Native recruitment acceptance target

Native `DefaultVolunteerModel.GetBasicVolunteer` supplies the culture elite base for rural notables whose village is bound to a castle; other sellers supply the culture regular base. This is a source-selection rule, not a global percentage. Upgrade/replenishment, notable availability and recruitment access remain separate concerns.

Amycon is Empire `castle_village_ES6_2`, bound to Sestadaim Castle (`castle_ES6`) in both base-game and War Sails settlement data. Its eligible rural notables should therefore supply the Imperial Vigla line when fresh slots are generated. Town sellers and town-bound villages must not acquire a new universal elite percentage.

Reign's existing `ReignGovernmentRuralVolunteerPatch` resolves a visiting rural notable's home/birth village because native code assumes that rural sellers are physically in a village. Preserve that safety behavior and prove that the compatibility patch neither clears volunteers nor moves notables. Existing occupied volunteer slots and upgraded troops are not a fresh-spawn test.

## Glove availability follow-up, 2026-11-11

The user reports no hand-slot armor in shops. RBM Combat changes 32 same-ID definitions from the installed native hand-armor set. None of those 32 overrides explicitly sets `is_merchandise="false"`; no blanket glove sales ban was found in the inspected hooks. Leather gloves change from 4 to 24 arm armor, and padded mittens from 9 to 31. Native hand-armor tier uses the combined armor values, a 1.7 hand multiplier and a -0.4 adjustment; RBM instead uses `ArmArmor * 0.1`. With these definitions leather gloves move from native tier-float 0.28 to RBM 2.4, and padded mittens from 1.13 to 3.1. These are source-derived calculations, not a live inventory census.

The installed native category selector uses the resulting item tier to choose garment/light/medium/heavy/ultra armor production categories. Native artisans have recipes for all five categories, and smithies for medium/heavy/ultra armor: a category shift is not proof of zero production. Within a requested category, native workshop item selection weights each eligible item by `1 / (max(100, item.Value) + 100)` and prefers town culture before a fallback. RBM's economic-tier and value changes therefore change production pools and relative selection weights even with Campaign disabled. They are a plausible contributor to scarcity, but the available evidence does not prove RBM is the sole cause of every empty shop.

Restore native economic tier, category, merchandise/culture metadata and production/drop weights alongside native item values. Add deterministic glove controls covering leather gloves, padded mittens and higher-tier metal gauntlets while retaining RBM physical armor. Native acceptance must observe registered item metadata, actual shop inventory and fresh production in a disposable campaign; do not promise that existing shops instantly refill or reset saved inventories. Evidence: `glove-definition-comparison.json`, `DefaultItemCategorySelector.native.cs`, `WorkshopsCampaignBehavior.native.cs` and `glove-availability-findings.json` in the retained audit directory.

## Proposed implementation

### Horse-price follow-up, 2026-11-11

Confirmed against the unchanged installed `RBMCombat.dll` hash and the installed native `TaleWorlds.Core.DefaultItemValueModel`, not only RBM's general settings description:

- With Combat enabled and Campaign disabled, `CalculateValue` still selects RBM's `CalculateLegacyValue`. For horses its derived base-value expression is `200 * E * M * A + B`; native uses `100 * E * A + B`, where `E = GetEquipmentValueFromTier(item.Tierf)`, `M = HorsePriceModifier`, `A = 1 + 0.2 * (Appearance - 1)` and `B = 100 * max(0, Appearance - 1)`. The observed multiplier is 1. This doubles the tier-based component for identical inputs, not necessarily a particular town's displayed price.
- RBM also overrides `CalculateHorseTier`: pack animals return 1; other horses use `0.009 * HitPointBonus + 0.03 * Maneuver + 0.03 * Speed`. Native uses `0.12 * Speed + 0.07 * Maneuver + 0.01 * HitPointBonus + 0.15 * ChargeDamage - 11.5`. Restoring the horse-price multiplier alone cannot remove either replacement.
- `RBMCombat_horses.xml` remains enabled with Troop Overhaul inactive. A same-ID raw-definition comparison found 50 horses with at least one difference among the reviewed economic/shared or physical fields; this count is not 50 proven changed retail prices. Sumpter Horse changes from explicit native `value="110"` to no explicit value. Work Horse changes from `value="130"` to no explicit value, appearance to 0.5, and merchandise flag to false. `empire_horse` (native Midlands Palfrey) changes appearance from 0 to 0.7 as well as physical/difficulty fields. Missing attributes are recorded as missing, not guessed default values. The earlier conversational label Imperial Charger for this ID was incorrect; the installed native XML identifies Midlands Palfrey.
- Campaign-enabled RBM would instead use `600 + 1000 * E * M` for derived horse value. That branch is currently disabled and must not be reported as the user's current formula.
- Native shop buy/sell quotes additionally depend on market, stock, perks, modifiers and transaction context. These source/data comparisons do not establish one universal retail multiplier or a current live shop quote.

The compatibility patch must explicitly restore native horse economic classification, base value/appearance and merchandise metadata, and native economic handling of horse modifiers, while retaining desired horse battle physics. Preserve horse IDs, ownership and saved inventories. Test pack animals, ordinary mounts, war mounts and noble mounts, comparing the same item, modifier, market/stock and buyer/seller context. Preserve native upgrade-eligibility categories. Do not obtain native prices by reverting the physical horse stats the user wants to retain; use the preserved pre-RBM economic baseline.

Evidence: `horse-data-differences.json`, `DefaultItemValueModel.native.cs`, `decompiled/RBMCombat/RBMCombat/ItemValuesTiers.cs`, and the retained native/RBM horse XML under `installed-originals/` in the audit directory. These are definition/formula findings; economic projection is implemented and locally verified above, while native market acceptance remains pending.
