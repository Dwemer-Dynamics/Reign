# Party chat continuation

Requested 2026-10-30. Ordinary Party Chat offers **Continue** directly below **All**, with **View** directly below **Clear**. Both reuse the complete label-free Clear plate pixels, the same 120×36 hit target, ReignSerifDynamic 15 typography and sound-only behavior. The source crop includes the whole integrated frame at 126×40, offset (-4,-2) relative to the hit target. No resampling, replacement shell, eye icon, separately aligned frame or oversized View hit target remains. The palette's disabledNeutral identifies unavailable labels. Geometry, provenance and decoded RGBA equality are registered in `ReignBeta/artwork/ui-modern-style-kit/specs/party-chat-continuation.json`.

## Behavior and persistence

Continue restores the latest ordinary-party conversation recorded in the **loaded native save**. All original participants, including people later deselected during that conversation, must still be eligible in the same settlement/room or at the same overland position. Additional available bystanders do not prevent continuation. There is no time-based expiry. The button is unavailable during generation, after this screen has begun/continued a conversation, or while an unsent draft would be overwritten. Homes, castle/family sessions, targeted reviews, NPC-initiated approach sessions and banter handoffs retain their own existing flows.

`ReignPartyChatHistoryBehavior` serializes one latest snapshot through native SyncData and `ReignSavePayloadCodec`. Old saves lacking the key load with no candidate. Blank screen openings and Clear selection never erase the last actual conversation. A new ordinary chat replaces it after dialogue begins. The snapshot stores the full displayed transcript, the existing last-36-line attributed model context, exact player input text, selected/original participant IDs, location, input/sequence counters and locally cached View-image paths. Clear still changes selection only; if that left no selected speakers, Continue selects the original group. Missing image files leave their saved captions, without generating replacement images.

Native-save ownership provides rollback isolation: an old save restores its own snapshot rather than looking up a newer server/cache transcript. Campaign/player identity, native campaign instance and load epoch fence publication. Stale screens cannot replace another loaded save's snapshot. The original place is captured when dialogue starts and is never rewritten merely by closing somewhere else. Presence is checked at the Continue click and again before sending/starting reply work.

Continue is local restoration. It makes no Approach request, dialogue/image generation request, native action, replayed player turn or server-session reopening. The old server transport has already been finalized, so Continue chooses a new transport ID on the **current** Save Sync timeline. The next intentional Send uses the normal session-start route and the restored attributed `groupTranscript`; old display exchange IDs remain intact, while restored monotonic counters give new turns fresh IDs. No server logical-conversation ownership or timeline check is relaxed. The on-screen transcript remains one continuous conversation. This does not migrate old transport-only internal reasoning or replay old actions.

## Consultation review

Claude, Grok (medium) and Gemini reviewed selected requirements and the implementation plan successfully. They did not inspect the screenshot or repository directly. All recommended exact plate/font reuse, complete removal of the old View hitbox, fresh transport identity, live presence checks, rollback isolation and provider-free restore tests. Current source confirms that the Clear plate contains no baked label and that the old View is a separate XML layer; no repaint is needed. Their advice to invalidate every timeline fork would defeat legitimate native-save continuation: this implementation instead restores only native-saved text and starts a new transport on the current timeline. Grok's suggested extra approval gate for implementing SyncData is not a project rule and is not adopted. Native acceptance and paid provider gates remain in force.

## Verification and acceptance

Provider-free behavioral tests exercise exact identity/place/member gates, extra bystanders, rechecking a departed member, overland movement, old-save rollback, selection-only Clear and a 3,002-line compressed native payload with attributed context and local image references. The UI contract checks the two control positions, fonts, source/atlas pixel equality, legacy control removal and available/unavailable/restored fixtures. Complete provider-free renders, fixed-shell fidelity and scoped typography are required separately.

Native acceptance remains required: save after a real ordinary party chat, quit/reload, press Continue, scroll to earlier turns, enlarge a saved local image and send the next typed reply without an automatic greeting. Repeat with a participant absent/dead/captured, a changed settlement/room or map position, extra bystanders, a different campaign and an older native save. Verify no duplicate messages/actions/Approach and no future transcript leakage. This task does not authorize launching Bannerlord, advancing a campaign or paid provider testing.
